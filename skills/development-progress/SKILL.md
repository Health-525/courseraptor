# 开发进度记录

使用本地知识库保存用户明确要求记录的开发工作，支持按项目回顾和整理日报、周报。普通编程问答不自动入库。

## 记录

- 用户明确要求记录时，先调用 get_time 确认当前日期；用户指定的工作日期优先，无法确定就问。项目名不明确时询问，不要猜测。
- 每次进展单独一条，调用 manage_knowledge 的 add。subject 使用「开发进度」；标题使用「开发进度｜项目名｜日期｜具体事项」，不同进展的事项应不同。先 list 按标题检索；如果同名记录已存在，调整标题以保留两条，避免 add 覆盖历史。
- content 写明项目、工作日期、已完成或正在做的事项；用户提及阻塞、下一步、关联链接时一并保留。未提供的字段省略，不编造状态、截止日期或成果。末尾注明「来源：用户口述」或实际来源。
- 成功后告知记录内容与保存位置（知识库），工具失败时如实说明，不能声称已保存。待办和提醒仅在用户要求时另用 manage_todos，遵守其截止日期规则。

## 查询和汇总

- 用 manage_knowledge 的 list 按「开发进度」分类查询，再按项目、日期和内容筛选；关键词是任一命中，不能把返回的所有条目都当成符合全部条件。
- list 最多返回 30 条；结果被截断时明确说明，必要时尝试更具体的关键词缩小范围。无法完整覆盖时不要声称汇总了全部记录。
- 日报、周报按已有记录整理已完成、进行中、阻塞和下一步，缺少的信息标明未记录；不将计划当成已完成。时间范围不明确时先问，或者说明采用的范围。
- 修改或删除时先查出目标条目及 id，按用户明确要求操作；对不明确的目标先询问。不要擅自修改或删除历史记录。
