# 发布包内置 HTTPS 授权与受控更新下载

这组改动把授权从可选的更新功能提升为正式发布包的启动前条件：发版脚本只接受 HTTPS 服务地址，并只在暂存副本中写入该地址；客户端随后在启动、更新和下载三个入口拒绝 HTTP。授权状态由服务端实时校验，没有保留本地时钟驱动的离线宽限；更新包在流式返回前复核密钥、状态和设备绑定。授权存储只保留密钥与随机安装 ID 的 HMAC，首次绑定以条件更新竞争，避免设备名称和并发首次激活留下原先的问题。文档、Nginx 模板和服务监听默认值与这条部署模型一致。Watch for: **confirmed** 该安全边界依赖按 `README.md` 与 `server/nginx.conf.example` 部署——Nginx 必须是唯一公网入口，Node 进程必须继续绑定 `127.0.0.1`。  
**Verdict**: APPROVED

## High-level view

发版链路不再将空默认地址带入安装包。`scripts/publish-release.mjs` 先拒绝非 HTTPS URL，再只替换暂存目录中唯一的占位符；发布包因此会执行 `ensureLicense()`，而源码工作区保留了文档明确声明的开发模式。该取舍不改变服务端分发边界：没有有效激活记录仍不能下载任何发布包。

客户端没有将密钥降级发到 HTTP：授权客户端在构建时拒绝 HTTP，`/update` 在发送下载头之前也要求 HTTPS，示例 Nginx 配置把 80 统一重定向到 443，Node 默认只监听回环地址。`/latest` 保持公开，只暴露版本元数据；实际包体必须通过服务端的实时授权检查。

授权状态以服务端时间和 SQLite 状态为准。禁用、过期、未激活或设备不匹配都会拒绝启动校验与新下载；设备重置后才允许重新绑定。管理员页面本身不持久化管理员令牌，创建、列表、禁用、启用和重置的 API 都在操作前检查 `x-admin-token`。

## 暂存发布包被强制接入授权服务器

`UPDATE_SERVER_URL` 在 `scripts/publish-release.mjs:37-42` 必须解析为 `https:`，失败发生在递增版本号之前。复制工作区后，脚本在 `scripts/publish-release.mjs:97-108` 只替换暂存副本 `src/update-check.ts` 中的精确占位符；占位符不存在即中止，而不会产生未植入服务器地址的 zip。注入值由 `JSON.stringify` 序列化，不能借 URL 文本改写 TypeScript 源码。

发布包中的 `getUpdateServerUrl()` 会使用该内置 URL，入口在 `src/index.ts:32` 无条件等待 `ensureLicense()` 后才构建 agent 或启动 QQ 桥。未配置地址时跳过授权仅发生在源码开发模式，且 README 在 `README.md:191-192` 明确写出这一约束。即使有人绕开本地启动校验，服务端的包下载仍单独受授权保护，因此不能借空默认地址取得发布包。

## HTTPS 覆盖密钥校验和更新包传输

`src/license.ts:33-45` 在创建客户端时拒绝非 HTTPS 地址，密钥只会在随后 `POST /license/activate` 或 `POST /license/check` 的请求体中发送。`src/update-check.ts:42-55` 对更新地址采用同一协议约束；`src/updater.ts:64` 在 `/update` 前强制校验，而 `src/updater.ts:95-98` 才附加 `x-license-key` 与 `x-device-id`。因此把 `RAPTOR_UPDATE_SERVER` 覆盖成 HTTP 只会使授权/更新失败，不会泄露这些凭据。

公网配置也与客户端约束闭环。`server/update-server.mjs:19-20` 默认绑定 `127.0.0.1`；`server/nginx.conf.example:7-13` 将 HTTP 重定向到 HTTPS，`server/nginx.conf.example:16-31` 才代理到回环 Node 服务，并启用 HSTS。这个模板本身不暴露可由外网直接访问的 HTTP Node 端口。

## 下载前实时复核授权，而非依赖本地宽限

`server/app.mjs:89-96` 从下载请求头取得密钥和设备 ID，并在 `server/app.mjs:177-183` 流式读取 zip 前调用 `store.check()`。`server/license-store.mjs:182-193` 以当前服务端时间校验状态、过期时间、绑定设备并更新时间戳；没有客户端时间、缓存成功结果或离线宽限参与决定。因此管理员禁用或到期会阻断下一次启动校验和下一次下载。

`tests/license-api.test.ts:96-132` 实测了已激活后禁用，随后 `/license/check` 与 `/download` 都返回 403；同一测试文件 `tests/license-api.test.ts:54-94` 还确认未带授权头的下载返回 401、不同设备返回 409。已授权的一个正在进行的下载不会在中途被撤销，但每个新请求都会重新检查，这是下载流的正常授权粒度。

## 最小化设备数据并让首次绑定只产生一个胜者

数据库模式在 `server/license-store.mjs:78-92` 只记录许可状态、备注、时间戳和 `device_hash`；没有设备名称字段。服务端不读取客户端请求中可选的 `deviceName`，公开管理视图也只展示是否已绑定，满足最小化数据的目标。

首次激活先验证密钥，然后执行 `server/license-store.mjs:101-105` 的 `UPDATE ... WHERE device_hash IS NULL`。`server/license-store.mjs:158-180` 检查受影响行数；落败请求会重读获胜绑定，只有同一设备可继续，另一设备得到 `device_mismatch`。这避免了先读空值、后无条件写入导致的双设备竞争覆盖。`tests/license-store.test.ts:30-59` 覆盖同设备复验、不同设备拒绝和管理员重置后的重新绑定；**confirmed** 当前测试没有以并发请求压力复现首次绑定竞争，但条件更新本身已覆盖该状态转换。

## 管理员接口和文档的边界一致

所有改变授权数据的入口均先调用 `requireAdmin()`：发布在 `server/app.mjs:156-168`，创建和列表在 `server/app.mjs:192-201`，禁用、启用和重置在 `server/app.mjs:204-210`。管理 HTML 只在浏览器内存中保留令牌，管理列表不返回明文密钥；`tests/license-api.test.ts:40-52` 验证了这项响应边界。页面写回备注与状态时使用 `textContent`，而落地页发布说明也转义 HTML 特殊字符。

`.env.example:35-41`、`README.md:163-207` 和 `server/nginx.conf.example:1-31` 都说明了同一模型：两个高强度服务端密钥、HTTPS 公网入口、回环 Node 服务、正式 zip 自动内置地址、下载需要已激活客户端。文档不再承诺落地页可直接取得 zip，和 `/download` 的服务端授权要求一致。

## 验证范围

在 Node `v24.8.0` 下执行 `npm test`，71 项测试全部通过，包括新增的 HTTP 拒绝、未授权下载、设备不匹配、禁用后检查/下载失效、明文密钥不出现在列表和设备名不持久化。`npm run typecheck` 也通过。

未对真实腾讯云、真实证书或最终发布 zip 执行端到端测试：当前审查没有使用真实管理员令牌或远端服务。静态发布脚本检查和单元/HTTP 测试已覆盖这次变更的本地行为；上线前仍应按模板在服务器上验证 Node 仅监听 `127.0.0.1`，并用一个测试密钥完成 HTTPS 激活、下载和禁用回归。
