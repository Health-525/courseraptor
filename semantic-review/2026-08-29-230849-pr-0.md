# 本地密钥隔离与 QQ 授权复审

本轮复审确认，上一轮的四个阻断项已在当前未提交实现中修复：`/Key` 等变体在卡片、行内和 QQ 的 Agent/history 边界前被本地处理；独立 `npm run qq` 先校验授权；激活密钥改由静音输入读取；行内旧式 `/key <secret>` 在写入 `readline` 前被吞掉。`npm test` 的 86 项测试通过，但新增回归测试使仓库的必经类型检查失败，当前变更无法通过 `npm run typecheck`。Watch for: **Required（confirmed）**：新增 QQ 启动和秘密输入测试违反严格 TypeScript 契约，阻断提交前验证。  
**Verdict**: NEEDS_CHANGES

## High-level view

当前唯一阻断来自测试辅助代码和其公开类型契约不一致。运行时测试可以执行，但严格编译会拒绝这些测试文件；在仓库的 `typecheck` 脚本恢复绿色前，不能将该变更作为可提交状态。

## 新增安全回归测试无法纳入严格编译门禁

**Required（confirmed）**：`npm run typecheck` 以 `strict: true` 编译 `src` 和 `tests`，当前以 7 个错误结束。`tests/qq-startup.test.ts:8-10,23-24` 将 `Array.prototype.push()` 的数字返回值直接作为 `async` 箭头函数的表达式结果，产生 `Promise<number>`，而 `src/qq/bridge.ts:225-227` 明确要求三个依赖返回 `Promise<void>`。`tests/secret-input.test.ts:15` 使用运行时有效的 `PassThrough` 驱动静音输入，但 `src/secret-input.ts:29-32` 将可注入流声明为更具体的 `NodeJS.ReadStream` 和 `NodeJS.WriteStream`，使该测试双身无法通过静态检查。

这不是可忽略的测试噪声：当前项目的 `typecheck` 脚本会在提交前/CI 中失败，且两处测试都是本轮四项安全回归的验证证据。应让 QQ 测试回调以块体显式完成 `push`，并把 `readSecret` 的注入边界收窄到它实际使用的通用读取/写入接口，或者提供满足现有声明的测试替身。修正后必须重新执行完整类型检查；仅凭运行时测试通过不能证明提交门禁可用。

</details>
