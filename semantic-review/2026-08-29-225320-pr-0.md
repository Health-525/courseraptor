# 授权启动与本地密钥隔离

这组改动把更新后台扩展为授权服务：后台为个人密钥绑定随机安装 ID，受控下载再次校验授权；发布包内置 HTTPS 服务地址，客户端启动时校验授权。`/key` 改为退出 TUI 后由本地静音流程读取，并在 QQ 渠道拦截该命令。**Watch for:** **Critical（confirmed）**：`/Key` 等大小写变体没有走本地密钥边界，会被交给 Agent；**Required（confirmed）**：独立 QQ 入口跳过授权，首次激活回显授权密钥，行内旧式 `/key <secret>` 会进入 `readline` 历史。  
**Verdict**: NEEDS_CHANGES

## High-level view

本地密钥命令依赖 `localOnlyCommandMessage()` 与两套 TUI 分发器阻止输入离开终端，但三处都把 `/key` 当作区分大小写的文本。命令菜单可以继续区分大小写；安全分类必须独立为大小写无关的边界，并在任何 Agent 调用和 QQ history 写入前统一执行。

授权校验只接在 `src/index.ts` 的交互式启动路径。`npm run qq` 直接执行 `src/qq/bridge.ts`，当前仅检查教务凭证便启动 Agent，形成一个公开的、已文档化的授权绕过入口。

敏感输入的正确路径已经使用静音 I/O，但首次激活仍使用普通 `readline`，旧式行内 `/key <secret>` 则在拦截前已经提交给 `readline`。这两条输入路径会把可复用密钥留下在屏幕或进程历史中，不能以“未调用 Agent”视为安全。

## 大小写变体绕过 API Key 隔离

**Critical（confirmed）**：`src/tui/slash-menu.ts` 的 `localOnlyCommandMessage()` 使用大小写敏感的 `^/key(?:\s|$)`，而 `src/tui/keys.ts` 只在 `cmdName in commands` 时走本地切换；`src/tui/inline.ts` 也只判断小写 `/key`。因此 `/Key sk-…` 在卡片模式被代理原样写给 TUI，在行内模式进入 `runOnce()`，在 QQ 模式通过 `localOnlyCommandMessage()` 后被加入 `userMsg` 并发送给 Agent。复现卡片代理收到的输出为 `"/Key sk-Secret…"` 和回车，`localOnlyCommandMessage("/Key …")` 返回 `undefined`。

菜单的大小写敏感过滤是补全定位的 UI 约束，不能承担安全策略。应在 `slash-menu.ts` 定义只处理命令词与边界的、大小写无关的本地命令判定；卡片原始输入代理、行内 prompt 分发和 QQ handler 全部调用它。这样既不会将 `/keyfoo` 误判，也不会让拼写大小写成为把 API Key 送到模型提供商的通道。

## 独立 QQ 启动绕过授权

**Required（confirmed）**：`src/index.ts` 在创建 QQ 桥和 Agent 前调用 `ensureLicense()`，但 `src/qq/bridge.ts` 的 `isEntry` 分支只调用 `ensureCredentials()` 后直接 `startQQBridge()`。`package.json` 将该分支暴露为 `npm run qq`，因此正式发布包的授权地址、激活状态、禁用状态和设备绑定都不会阻止独立 QQ Agent 启动。

应让两个入口复用同一个“授权完成后再构建 Agent/启动渠道”的编排，而不是靠主入口偶然覆盖嵌入式 QQ。回归测试需要验证直接入口在授权失败时不调用 `startQQBridge()`，但没有配置发布地址的源码开发模式仍可启动。

## 首次激活回显授权密钥

**Required（confirmed）**：`src/license.ts` 的 `activateInteractively()` 在普通 `readline` 上执行 `rl.question("请输入 CourseRaptor 激活密钥: ")`。普通 TTY 会回显输入，所以首次激活这个正常流程会把可继续绑定/下载的密钥留在终端缓冲区；这与 `/key` 的静音读取保证不一致。

将许可密钥也视为秘密输入：抽取可复用的静音 `readSecret`，在 API Key 设置和激活流程中使用同一实现，并以捕获输出的测试证明密钥不会出现。许可证仍可在 HTTPS 请求体和本机加密存储中使用，无需通过普通输入行传递。

## 行内拒绝发生在历史写入之后

**Required（confirmed）**：`src/tui/inline.ts` 先等待 `readline` 的 `line` 事件，再以 `/^\/key(?:\s|$)/` 打印拒绝提示。实际 `readline` 语义会在 `line` 事件前将该行加入 `rl.history`；复现输入 `/key sk-Secret…` 后，`rl.history` 包含完整字符串。终端同样已回显这条已提交的旧式命令。

处理应前移到 raw-input 层：识别到本地 `/key` 命令和其后的空白后，不再把后续秘密字节写入 `readline`，清除当前行并提示改用无参命令。若保留行级拦截，则必须删除 history 条目和重绘为无秘密提示；只保证不调用 Agent 无法满足不泄露的约束。

## 验证覆盖未覆盖秘密边界的变体

`npm test` 通过 81 个测试，`npm run typecheck` 通过。

**Not tested:** 大小写 `/Key` 在卡片、行内与 QQ 的阻断；独立 QQ 入口的授权失败；首次激活的静音回显；被拒绝旧式命令不进入 `readline` history 或终端缓冲区。这些缺口对应上述阻断项，现有绿色测试不能证明密钥边界完整。
