# 学生功能路线图

[返回首页](../README.md) · [提交建议](https://github.com/Health-525/courseraptor/issues/new?template=feature_request.yml)

服务对象：南京工业大学学生，先解决日常查询与上手体验，再扩展持续使用场景。下面是基于当前代码与使用流程的产品判断，尚未经过学生访谈验证；优先级不是上线承诺。

## 本轮已完成

- 免教务账号、免 API Key 的离线演示，使用正式网页视图与虚构数据。
- 启动自检和 Windows Node.js 24 版本检查。
- 学业概览：已获学分、未通过课程、待确认课程、数据是否完整。
- 修正未知成绩被当成通过型、未通过通识课程计学分、通过型重修优先级等问题。
- 网页常用问题增加通识检查与日历导出，并说明模型服务的数据去向。
- 安装包排除本机数据，升级保护聊天、附件、生成文件和个人校历记录。
- 学生 README、分层文档、贡献指南、问题表单与 CI 配置。
- 网页会话搜索、改名、置顶与窄屏会话抽屉。
- 浏览器文件上传、课表/成绩/考试/通知结果卡和手动刷新变化对比。
- 设置连接检测、通知截止日期待办、`.ics` 导出与本地数据导出/清理。
- 本周课表独立页（`/today`）：按周课表完整展示课程，支持切换教学周；纯本地缓存渲染（新增考试缓存），不登录教务、不调模型。

## 下一步优先做什么

| 优先级 | 功能 | 学生得到什么 | 首版范围 | 验收标准与依赖 |
|---|---|---|---|---|
| P1 | ~~本周课表~~ **已完成**：独立页 `/today`，断网显示缓存时间 | 打开即可完整查看任意教学周的课程 | 从缓存以周课表展示课程，支持切换教学周 | 断网显示旧数据时间；单双周、调休正确；不每次打开都调用模型 |
| P1 | 截止日期待办与提醒 | 少错过报名、补选、材料提交 | **网页首版已完成**：通知原文提取日期 → 用户确认 → 本地待办和 .ics；后续再评估程序关闭后的系统通知 | 每条有原文来源；支持完成；日期不明确时不自动创建 |
| P1 | 成绩/课表变更对比 | 知道新增成绩、换教室或考试改期 | **网页首版已完成**：手动刷新时与上次成功快照比较；后台监控另行设计频率与授权 | 请求失败不覆盖快照；只提示实际变化 |
| P2 | 培养方案核对 | 知道差哪些类别、差多少学分 | 用户提供本人年级/专业培养方案，确认规则后核对 | 保留规则版本与原文；未通过不计学分；不宣称代替毕业审核 |
| P2 | 选课冲突与备选比较 | 找到时间不冲突、满足类别的课程 | 对比课程时间、教师、类别、学分、余量 | 覆盖单双周和部分周重叠；缺少时间字段时标记无法判断；先做只读比较 |
| P2 | 考试复习计划 | 把考试日期变成可执行复习安排 | 按考试先后、用户可用时段生成计划和可编辑待办 | 不把所有空课时都视为可用；支持休息与延期；修改后能同步更新 |
| P2 | 安装与配置进一步简化 | 不熟悉终端的学生也能顺利完成首问 | **网页已完成连接检测**；后续补首次配置分步向导和恢复入口 | 新设备按文档完成安装；未配置也能浏览帮助；凭证不进入聊天历史 |
| P3 | 成本与数据管理 | 清楚哪些内容发给模型、如何清理历史 | 本地用量概览、导出/清理本人数据 | 以实际返回用量为准；清理前预览范围并确认；不默认上传行为分析 |
| P3 | 多校适配 | 其他学校也能使用 | 先抽离学校接口与校历/绩点规则，再新增一个可测试适配器；边界见 [Adapter 设计说明](writing-an-adapter.md) | 学校配置和测试样例独立；不把“同为正方”当成兼容保证 |

## 暂不优先

- 空闲教室、图书馆占座等依赖尚未核实可用接口的功能，先调查数据来源。
- 无来源的毕业资格判断、奖学金排名预测和自动替学生提交申请。
- 共享一套教务凭证的多用户服务。QQ 白名单不是多账号隔离。
- 将“抢课成功”作为推广主卖点；长期价值应来自日程、通知和学业查询。

## 如何决定下一个版本

先邀请少量自愿参与的同学，分别完成安装、首次查课表、通识核对、日历导出四项任务。只记录是否完成、卡在哪一步和是否愿意继续使用，不收集成绩、学号或完整聊天。

优先修复多人重复遇到的阻碍，再从上表选择一个需求做完整闭环。功能建议应描述“什么时候需要、现在怎么解决、怎样算好用”，而不只是工具名称。
